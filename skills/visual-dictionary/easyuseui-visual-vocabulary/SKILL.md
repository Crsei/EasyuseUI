# 视觉词典：从外观到语义

把“长什么样”转换为“它负责什么、叫什么、可以用什么实现”。不要因外观相同就给两个行为不同的对象使用同一组件。

## 先确定使用模式

- **使用 EasyuseUI 组件：** 在本仓库或安装了本库的消费项目，识别术语后核对目标版本源码导出、类型、Catalog 和 Registry。区分已有、内嵌、基础、待实现、视觉参考；词典收录不构成导入承诺。
- **不使用 EasyuseUI 组件：** 以本技能的词汇和语义解释需求，映射到目标项目已有库或 HTML/CSS。不要引入本库、`@/components/` 路径、主题或本机服务。目标库可能使用不同名称，以行为与可访问性判定是否等价。

本仓库实现默认第一种；外部项目无本库依赖且未要求采用时默认第二种。模式已由任务明确时直接执行。

## 工作方法

1. 记录可见特征：形状、位置、层级、密度、出现方式。截图不能证明点击、键盘、权限或后端行为，未见事实标为待核实。
2. 判定职责：只读信息、选值、执行动作、导航、内容切换、对象详情或临时反馈。用户已有明确意图时以意图为准。
3. 给出中英文术语和必要别名，分开写形状与语义。例如“可移除 Chip，胶囊外观”。
4. 需要选型时读取 [词汇与边界](references/vocabulary.md) 的对应条目；只有复用模式需要核对其中的 EasyuseUI 实现入口。
5. 输出组件候选、真实实现情况以及会改变选型的交互条件。缺少 API 时说明缺口，按目标项目规范补齐，不编造 import。

## 必须保留的区分

| 容易混淆                              | 判定原则                                                        |
| ------------------------------------- | --------------------------------------------------------------- |
| Pill / Badge / Tag / Chip             | Pill 是形状；Badge 读状态；Tag 读分类；Chip 选择或移除值        |
| Tabs / Segmented Control / Navigation | 同对象面板切换 / 一个互斥设置值 / 去另一个位置                  |
| Menu / Select / Popover / Tooltip     | 执行动作 / 选择值 / 锚定的补充内容 / 简短解释                   |
| Dialog / Modal / Drawer / Inspector   | 内容容器 / 阻断背景的交互模式 / 空间呈现方式 / 当前对象详情职责 |
| Shadow / Elevation / z-index          | 阴影画法 / 覆盖层级关系 / CSS 叠放顺序，不能互相替代            |
| Skeleton / Shimmer / Loading          | 结构占位 / 可选扫光效果 / 数据或操作等待事实                    |

Tooltip 不承载审批或唯一错误；Toast 不承载需要持续处理的问题；AI 身份色不证明思考中或成功。渐变、玻璃、发光等可用于明确的风格任务，紧凑工具页仍以信息层级和中性表面为基线。

## 复用模式的来源核对

在 EasyuseUI 根目录读取 `Design-rules.md`、`Component-Specification.md` 后，查 `UI-VISUAL-DICTIONARY.md` 和 `lib/visual-dictionary.ts`。组件导出以 `components/ui/`、`components/blocks/` 为准，演示和分发核对 `lib/catalog.ts`、`registry.json`。消费项目以实际安装位置和版本核对，不假设与本仓库别名一致。

只有已运行时才访问 `/dictionary/`；不要为了术语查询启动或重启服务。无源码时明确哪些映射尚未核实，先完成不依赖这些 API 的识别工作。

## 输出与自检

普通术语问题简短回答即可；涉及实现时按下列信息组织：

```text
外观描述：
职责与术语（中英文）：
形状/效果：
使用模式与组件候选：
已核实能力与未核实交互：
键盘/触摸/状态的必要条件：
```

检查是否把外观当行为、把内嵌能力当独立 API、把截图当真实服务证据，或为了术语沟通引入了用户未要求的依赖。
