# 组件复用与独立实现

按目标项目已有能力推进，明确组件、适配层、执行服务各自负责什么。

## 决定使用模式

- **使用 EasyuseUI 组件：** 本仓库或消费项目已有本库组件，优先组合真实导出；读库根目录`Design-rules.md`、`Component-Specification.md`，再按任务核对[组件映射](references/component-map.md)、源码类型、Catalog与Registry。
- **不使用 EasyuseUI 组件：** 沿用目标技术栈与组件库，按下述独立契约实现。不要为了使用原则安装EasyuseUI、拷贝文档站、重建脚手架或引入`@/`别名。尺寸采用目标正式规范，本库紧凑数值仅作基线。

本仓库默认复用；外部未依赖且未要求采用时默认独立实现。用户指定其他组件库时直接按其API实现。混合页面按区域标明来源与缺口。

## 使用 EasyuseUI 组件

1. 查现有组件和消费项目安装路径，读实际props及示例。`@/components/`仅是本仓库约定，消费项目alias可能不同。不要从词典词条猜测导出。
2. Foundation→Primitive→Product Pattern→Workspace→Page逐层组合；公共组件保持独立于文档站、账号、网络服务和路由。页面通过适配层提供业务数据与能力。
3. 共享值消费主题，运行状态复用字典和`RuntimeStatusBadge`，五种数据态复用`DataRegion`。缺少功能时扩展正确层级，避免页面复制一套业务行、对话或分栏markup。
4. 改库内可分发组件时，同步工作示例、`lib/catalog.ts`、`registry.json`及依赖。CSS Module、工具函数和内部Registry依赖完整登记，不依赖消费项目碰巧拥有文件。
5. 只在需要安装本库时检查消费项目兼容性和Registry来源。React/TypeScript/Tailwind 4是当前分发约定，按目标版本核对；主题安装可能更新消费项目CSS，先审查现有主题再作局部整合。

消费项目使用既有组件不要求改本库Catalog或启动本库文档站。源码/类型不可用时说明未核实能力，继续完成不依赖该API的部分，不伪造可编译代码。

## 不使用 EasyuseUI 组件：可迁移契约

| 对象                  | 实现应满足的语义与行为                                                                         |
| --------------------- | ---------------------------------------------------------------------------------------------- |
| Button/Input          | 动作与导航语义正确；字段有label；busy防重复，错误保留输入并关联说明；图标动作有名称与提示      |
| Item/业务行           | 名称、关键状态、次级元数据层级清楚；主目标与尾部动作是兄弟，静态行无假hover；选择不执行任务    |
| Badge/Tag/Chip        | 只读状态/分类与可操作值分开；Chip选择/移除为独立目标，busy保留值，移除后恢复合理焦点           |
| Tree                  | 真实父子关系、稳定ID；单选与展开受控；方向键、Home/End、前缀定位及折叠焦点恢复；移动有键盘替代 |
| Activity              | 稳定事件ID去重、来源顺序；五种数据态；阅读历史时不抢滚动，距底部≤64px才跟随                    |
| Inspector/Shell       | 完整受控对象快照；按ID丢弃迟到响应；布局与对象数据分责；resize键盘可用，浮层约束并恢复焦点     |
| Conversation/Composer | 消息同轴，工具记录独立；草稿与消息态分开，IME不误发；失败保留内容，补历史保留锚点              |
| Tool记录              | 身份/参数/结果/审批/读取态/结果确认分开；先脱敏，有界预览；unknown先对账，取消等待确认         |

使用目标项目已有可访问组件或原生元素；ARIA角色必须配套行为，不能只给普通列表添加`role="tree"`。不需要实现本次任务没有使用的全部对象或状态。默认紧凑基线是4px间距、32px控件、中性表面、1px分隔；触摸目标至少44×44，焦点与选中分离。

## 两种模式共同的边界

组件不建立第二份业务存储；调用方持有对象ID、请求、缓存、权限、真实执行、传输与持久化。只有显式提供的能力才显示可操作入口。回调resolve只证明请求提交，不等于运行完成。未知结果保留回执先对账，不以计时器、toast或本地数据改动证明服务成功。

所有数据区覆盖loading/empty/partial/error/success。刷新失败保留同对象旧内容，切对象不混数据。输入、部分文本和既有输出在失败时继续可读；复制和导出走同样的脱敏边界。

## 验证与交付

- 改EasyuseUI时遵循`AGENTS.md`：先查进程/端口，复用服务，保留并行改动；本机使用Webpack。组件实现后运行lint、typecheck、build，行为变化加浏览器测试，分发依赖/源码/CSS变化加独立安装验证。
- 消费项目或独立实现使用目标项目规定的检查命令；不照搬本库pnpm、3010/3011端口或本机GLIBC约束。
- 交付说明模式、复用/新增位置、调用方接入点、通过的检查和未验证范围。fixture交互、独立安装、真实服务执行及业务验收分别记录。
