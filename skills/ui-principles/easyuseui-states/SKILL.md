# 状态分轴与恢复

先写已知事实与权威来源，再设计状态展示和可执行动作。请求成功、数据可读、运行完成、业务验收是不同事实。

## 使用模式

- **使用 EasyuseUI 组件：** 先读库根目录 `Design-rules.md` 和 `Component-Specification.md`，再按需读 `UI-STATES.md`；复用 `DataRegion`、`RuntimeStatusBadge`，以 `lib/runtime-status.ts` 为统一字典。具体属性和组合见 [状态接入](references/state-integration.md)。
- **不使用 EasyuseUI 组件：** 使用下述状态轴和恢复语义，在目标项目定义集中类型/映射及展示。状态名可匹配现有服务，不要求导入本库十种枚举；不能丢弃未知值和不确定结果。

本仓库默认复用；外部无依赖且未要求采用时默认独立实现。不要为了增加一个页面提示扩充本库 runtime，先判断提示属于哪个轴。

## 独立状态轴

| 轴             | 事实                                                        | 规则                                               |
| -------------- | ----------------------------------------------------------- | -------------------------------------------------- |
| 交互           | hover、pressed、focused、selected、disabled、busy、控件错误 | focus与selection可同时存在；busy防相同动作重复提交 |
| 数据           | loading、empty、partial、error、success                     | 只说明当前区域读取是否完整可用                     |
| Runtime        | 排队、启动、运行、等待、终止等                              | 只由运行权威来源确认                               |
| 消息           | 提交、接收、中断、失败、停止                                | 不直接推导底层任务/工具结果                        |
| 连接与新鲜度   | 在线/断开、刷新、最后更新时间                               | 叠加在已有 runtime 与内容上                        |
| 权限与能力     | 无权限、需批准、能力未提供                                  | 操作由调用方授权及回调决定                         |
| 请求与结果确认 | 提交中、已提交待确认、known/unknown                         | resolve不证明执行完成；unknown先对账               |

disabled阻止操作，busy阻止相同动作，错误说明保持可见；静态行的hover、普通提交按钮的selected可以是语义上的不适用，不是要求给每个元素套全套状态。

## 五种数据态与恢复

| 情况           | 展示与恢复                                         |
| -------------- | -------------------------------------------------- |
| 首次无数据加载 | 最终结构的 Skeleton；aria-busy；不显示可点击假行   |
| 成功读取但为空 | 说明未创建/筛选无结果/未选择，给对应的真实下一步   |
| 部分内容       | 保留可用内容，缺失“—”，说明未完整范围，按能力补载  |
| 初次读取失败   | 错误分类、已知原因或尚未确认、恢复入口；不冒充空态 |
| 同对象刷新     | 保留旧内容和轻量更新提示，不换成整屏骨架           |
| 同对象刷新失败 | 旧内容+错误+过期提示+最后更新时间，重试安全读取    |
| 读取成功       | 正常展示；不据此把 runtime 改成 completed          |

刷新和更新时间不新增第六种数据态。对象切换按 ID 丢弃迟到响应；旧快照只可保留给同一对象，不可在新对象下短暂复用。可选字段合法缺省不必一律标 partial。

## Runtime 语义基线

| EasyuseUI 值                   | 含义                     | 显示补充信息                                   |
| ------------------------------ | ------------------------ | ---------------------------------------------- |
| idle / queued                  | 待命 / 已排队            | idle不等于offline；队列位置仅在来源提供时显示  |
| starting / running             | 启动 / 执行              | 当前阶段与耗时；实际可计算才显示进度           |
| thinking                       | 来源明确报告推理/规划    | 不从暂时无输出或紫色身份推断                   |
| waiting / paused               | 等外部条件 / 已确认暂停  | 等待或暂停原因；能力决定输入、审批、继续等入口 |
| completed / failed / cancelled | 已确认完成 / 失败 / 取消 | 保留结果、错误与历史；completed不代表业务验收  |

未知 runtime显示“未知状态”和原始值，不能回落到idle或绿色。断线保留最后确认状态并标明过期，不自动改failed。点击取消后显示已提交待确认，收到来源确认后才cancelled。独立实现按服务真实状态映射这些语义，不强迫 provider 服从固定转换图。

## 错误、消息与受控输入

错误分 validation/request/runtime/agent/permission/network；说明发生什么、已知原因、下一步。不能从网络错误推断 Agent failed，从长消息推断上下文超限，或从缺失退出码补0。

消息区分pending/streaming/completed/interrupted/failed/cancelled；草稿是输入状态。失败保留草稿和已收文本；停止接收不等于取消任务。Enter发送、Shift+Enter换行、IME期间不误发；异步提交防重复。新增内容仅在距底部≤64px时自动跟随，补历史保留锚点。

## 工具执行与审批

1. 工具身份、最后runtime、详情读取态、批准需求和结果确认分别表达。
2. 显示对象、目标、作用范围与风险，只有用户明确触发且有授权能力时批准/拒绝。展开和选中不批准。
3. 请求期间防重复；回调resolve只表示请求已提交，由来源更新最终快照。
4. 超时、响应丢失或回调失败可能已产生副作用，标明unknown，保留call ID、receipt和已有输出。
5. 先查询/对账，再决定后续动作。未知结果期间不自动重新写入；不能靠重挂载或清本地busy绕过确认。

重读详情、重新执行、查询执行结果是三种能力。预览、复制、导出前统一脱敏；预览有界，来源只给片段时不宣称完整输出。空输出不证明失败或成功。

## 实现与验收记录

按任务需要记录：对象ID/范围、各状态轴与来源、空态原因、部分数据、旧内容保留、错误恢复、真实能力、未知结果对账、键盘触摸和证据等级。至少检验“running时读取失败”“切B后A迟到”“取消只回已接收”“工具响应丢失”四类适用场景，不通过定时器伪造完成。
