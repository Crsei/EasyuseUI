# UI 契约验收

围绕本次交付行为检查，给出可定位的问题和有边界的证据。用户只要求审查时保持只读，不把验收自动扩展为修改、部署或真实工具写入。

## 使用模式

- **使用 EasyuseUI 组件：** 先读库根目录`Design-rules.md`和`Component-Specification.md`，按任务核对相关组件API、示例、Catalog与Registry；正式契约是本库验收标准。
- **不使用 EasyuseUI 组件：** 按目标项目正式契约及用户明确要求检查，采用下述通用原则；记录与紧凑基线的合理差异，不把未使用本库、变量名不同或未建Registry算缺陷。

本仓库默认复用，外部无依赖且未要求采用时默认独立实现。纯文档改动做结构、路径、术语与来源校验，不为了验收触发网络执行或编造浏览器覆盖。

## 检查顺序

1. 明确任务、页面/组件、使用模式、对象身份、真实能力与修改范围。
2. 先查会改变结果的语义和责任：选择与执行、权限、数据来源、结果确认和敏感内容。
3. 再查信息层级、密度、主从职责、状态与恢复、长内容和可访问性。
4. 按适用范围选择[验收场景](references/scenarios.md)，运行仓库要求的检查；已通过检查不无故重复。
5. 将发现与具体路径、触发步骤、预期/实际及证据关联，分清已通过、部分、未通过和未验证。

## 必查原则

| 类别      | 验收点                                                                  |
| --------- | ----------------------------------------------------------------------- |
| 层级      | 能识别当前页面、对象、重要状态和下一步；普通运行列表没有层层Card        |
| 一致性    | token有统一来源；同状态不因页面改变标签/颜色；单区域主操作明确          |
| 语义      | 动作用button，导航用link；只读标签不冒充按钮；Item/Chip无嵌套目标       |
| 交互      | 静态行无假hover；focus与selected分离；图标有名称和解释                  |
| 数据      | 五态完整；无权限不冒充empty；partial不补假0；刷新失败保留同对象旧数据   |
| 并发      | 切对象丢弃旧响应；事件稳定ID去重；历史阅读与补载不抢滚动                |
| 权限/执行 | 展开不批准；能力真实；提交与结果分开；unknown先对账再写入               |
| 安全展示  | 参数、输出、错误、复制与导出同一脱敏边界；预览有界且不伪称完整          |
| 可访问性  | 键盘能完成；触摸真实命中至少44×44；模态焦点/退出/恢复；减少动态效果可用 |

EasyuseUI尺寸按正式契约验收；独立实现尊重目标规范。截图只能验证可见外观，不能证明完整键盘、滚动、请求或后端执行。

## 工程验证

改本库实现后按`AGENTS.md`运行`pnpm lint`、`pnpm typecheck`、`pnpm build`；行为变化运行浏览器测试，分发源码/CSS/依赖变化运行`pnpm test:install`。先检查进程、端口与并行工作，复用已有服务，避免构建覆盖活动服务产物。其他项目使用自身命令。

不把全套框架命令套在仅复制技能包的任务上；若当前仓库明确要求则遵循。测试失败区分产品缺陷、环境限制、并行产物冲突和范围外既有问题；保留证据，不将未完成写成通过。

## 证据等级与输出

| 证据               | 可以证明                           | 不能单独证明                 |
| ------------------ | ---------------------------------- | ---------------------------- |
| 源码/类型/静态检查 | API、结构及可分析约束              | 浏览器交互或真实执行         |
| fixture浏览器测试  | 所测状态、布局、键盘/滚动行为      | 登录、provider或真实工具成功 |
| 独立安装           | 分发文件、依赖和消费项目编译       | 真实服务接入                 |
| 已认证真实服务验证 | 指定来源、对象、环境下的已确认结果 | 用户业务验收或其他环境       |
| 用户业务验收       | 用户确认的业务条件                 | 未检查的其余范围             |

交付先说结论和主要问题，再给检查结果与剩余证据边界。问题标严重程度与文件位置；无问题也说明检查范围。与任务无关的风格偏好不作为必须修复项。
