# Agent 工作台网页展示计划

日期：2026-10-09。状态：M0–M5 已完成，M6 为后续服务集成；见 [实施记录](./agent-workbench-implementation-log.md)。

组件现状、产品调研、模型与服务边界见 [组件建设计划](./agent-workbench-components-plan.md)。本计划规定用户怎样逐区查看，再怎样进入完整产品网页。

## 1. 展示层级

按“区域实验室 → 布局组合 → 完整工作台”顺序建设；第一阶段就能在网页单独看侧边栏、上下文、对话和输入区，后续页面继续使用这些区域组件。

| 层级 | 拟定入口 | 目的 |
| --- | --- | --- |
| 展示导航 | `/examples/agent-workbench/` | 三个入口及当前完成状态；说明本地交互范围 |
| 区域实验室 | `/examples/agent-workbench/regions/?region=sidebar` | 一个区域一屏，查看视觉、交互和状态 |
| 布局组合 | `/examples/agent-workbench/layouts/?layout=conversation` | 相同数据下比较对话/审阅/任务三种布局 |
| 完整示例 | `/examples/agent-workbench/app/?template=coding&page=home` | 连续操作的产品页面，弱化展示控件 |

沿用静态导出，使用固定路由加query，不为fixture会话生成动态服务路由。URL中的region/layout/template/page/session/panel使用白名单解析；非法对象显示可恢复的未找到状态。只有导航状态进入URL，草稿、上下文正文与凭据不进入URL。

`SiteFrame` 对完整示例及组合页采用全窗口布局；区域实验室保留轻量展示导航。新增精确路由规则，不改变现有工作台和营销页。浏览器前进/后退恢复正确页面与会话，不额外启动任务。

## 2. 第一阶段：区域实验室

桌面布局：左侧区域目录，中间真实组件预览，右侧可折叠场景控制；底部折叠“组件映射 / 数据合同 / 验收说明”。移动端目录改成选择器，控制区放Sheet，主预览占满剩余宽度。

预览可选浅色/深色、中文/英文、桌面/窄屏容器。场景选择进入query便于分享。控制面板只修改本地fixture；默认显示“本地交互示例”，真实产品控件不展示内部reducer、schema等实现细节。

| 顺序与区域 | 预览内容 | 必须能操作的行为 | 必备场景 |
| --- | --- | --- | --- |
| R1 Sidebar | 新任务、项目分组、运行中/最近/归档、底部设置 | 切换项目/会话，搜索，折叠，收藏/重命名/归档本地fixture | 无项目、无会话、长标题、未读、运行与等待并存、过滤为空、加载失败 |
| R2 Context | 引用列表、文件选区、规则/技能来源、用量说明 | 添加/移除引用、查看来源、选择文件、失败重试 | 空引用、重复、上传中、失效、无权限、截断、用量未知/估算/超限 |
| R3 Conversation | 用户/Agent/系统记录、代码、引用、工具、结果 | 复制、展开工具、返回最新、加载旧历史、定位关联产物 | 首次加载、长历史、生成中、断线、失败、取消、迟到事件 |
| R4 Composer | 草稿、附件、模型、权限、发送/停止、队列 | IME输入、附件选择、@引用、修改模型、发送失败保留草稿 | 空输入、提交中、无连接、能力不支持、unknown、排队与steer各自确认 |
| R5 Header | 会话标题、项目/分支/环境、运行状态与面板开关 | 重命名、切面板、打开环境详情、请求停止 | 未选择环境、只读、等待批准、断线、取消请求未确认 |
| R6 Tools & approval | ToolCall + ApprovalRequestPanel + 问题面板 | 展开脱敏输出、批准/拒绝fixture、回答问题、对账 | 超长输出、失败退出、无输出、重复点击、审批过期、回执丢失 |
| R7 Files & review | 文件树、文本、Diff、行反馈草稿 | 定位文件/行、切统一/并排、添加/编辑/移除反馈 | 新增/删除/重命名、二进制、长行、版本改变、部分数据、无变更 |
| R8 Output & preview | 命令日志、测试结果、产物预览 | 过滤/复制日志、查看产物、切换预览、重连fixture | 截断、测试失败、断开、预览不可用、无PTY能力 |
| R9 Plan & artifacts | 计划步骤、Trace、ArtifactList、ReviewSummary | 从步骤找工具，从产物回到消息，从审阅找文件 | 未计划、进行中、等待、已产出未审阅、已审阅未验收 |
| R10 Inbox & settings | 关注队列、环境/模型/权限配置 | 找待处理任务、选择配置、恢复示例默认值 | 无待办、能力受限、配置无效、刷新失败保留内容 |

R1–R4先完成并上线本地展示，再继续R5–R10。每区提供“在组合布局查看”入口，携带当前session与scenario；公共组件通过同一套props接入，不把实验室控件写入公共组件。

## 3. 第二阶段：组合布局

| 布局 | 页面组织 | 适用任务 | 必验行为 |
| --- | --- | --- | --- |
| L1 对话优先 | 左SessionNavigator，中Conversation+Composer，右Context/Inspector，底栏收起 | 提问、计划、持续执行 | 添加上下文后发送；审批回执同步到消息、侧栏、详情；正文不被自动滚动打断 |
| L2 审阅优先 | 左会话可折叠，Main为窄对话+宽Files/Diff，属性按需打开 | 检查代码、产物反馈、测试结果 | 行评论进入反馈草稿；版本切换防止错行；返回对话保留草稿和阅读位置 |
| L3 任务优先 | 左项目，中运行列表/AttentionQueue，右选中任务详情；进入任务打开会话 | 多任务监控、处理等待、查看失败 | 列表选择仅导航；打开会话与审批是不同动作；排序变化不丢选择 |

三种布局共用一个受控workbench状态，不复制会话数据。L3复用现有Agent Board能力，与当前 `/workspace/agents/` 相互链接，保留原展示入口。

视口检查：1440×900、1280×800、1024×768、768×1024、390×844；另测200%缩放、粗指针和reduced-motion。尺寸示例用于验收，不写死设备识别逻辑。

宽Diff属于Main空间；Inspector保持元数据职责。当两栏最小宽度放不下时切换单面板，不能把正文挤成几字一行。面板展开、折叠、切换和拖动尺寸都可用键盘完成。

## 4. 第三阶段：完整页面设计

完整示例使用自己的紧凑导航与真实页面结构，进入后不围绕每区画说明边框。场景切换、重置和组件说明收纳到“示例设置”；固定轻量本地示例标识。

| 页面 | 页面设计 | 主要操作与去向 | 状态和边界 |
| --- | --- | --- | --- |
| Home / New task | 项目选择、紧凑任务输入、最近会话、等待处理摘要；不用大幅营销Hero | 选环境/模型/权限，输入后创建fixture会话 | 首次使用、无项目、缺少环境、创建失败；创建确认后再进入会话 |
| Project | 项目信息、环境/分支、会话列表、关联产物 | 新建任务、继续会话、筛选运行状态 | 无会话、只读项目、环境断开；选择分支不执行checkout |
| Session | L1默认；任务标题、消息流、输入和上下文 | 发送、停止请求、审批、查看文件/产物、切L2 | 草稿/提交/运行/等待/中断/失败/完成；来源确认决定结果 |
| Review | L2；变更范围、文件列表、Diff、反馈、测试/审阅摘要 | 批量整理行反馈并送入会话草稿；确认发送后回会话 | 无变更、版本过期、冲突、部分Diff；不以本地“已查看”代表Git批准 |
| Inbox / Runs | AttentionQueue + 运行列表；待批准/待回答/失败/待审阅筛选 | 进入对应会话和具体工具/产物 | 无待办、读取失败、过期动作；不能批量隐式批准 |
| Artifacts | 产物列表与预览，来源会话和生成时间 | 预览、复制、下载本地可用产物、回到来源 | 无产物、格式不支持、读取失败；下载按钮只在确有数据时启用 |
| Settings | 外观/语言、模型与环境、权限、工具能力，按栏目显示 | 修改本地示例偏好、查看不可用原因、重置 | 演示只保存明确的本地偏好，不伪装成已连接模型或MCP服务 |

归档会话通过侧栏列表恢复；搜索通过CommandPalette统一打开并定位会话。自动化、插件市场、计费、团队管理属于后续产品范围，V1不制作空壳页面充数。

## 5. 三种完整网页类型

模板是同一组件系统的场景配置，每个都有可连续操作的内容与闭环。它们不是三个彼此复制的前端项目。

| 模板 | 导航与默认布局 | 连续场景 | 复用重点 |
| --- | --- | --- | --- |
| T1 Agent 编码工作台（主样板） | 项目/会话侧栏，L1；审阅时切L2 | 修复过滤逻辑 → 查看计划 → 工具审批 → 测试失败 → 追加反馈 → 查看Diff与产物 | SessionNavigator、AgentConversation、AgentComposer、ContextPanel、ChangeReviewPanel |
| T2 产物与审阅工作台 | 项目/产物/最近会话；产物预览优先 | 分析资料 → 生成报告fixture → 定位引用 → 整理审阅意见 → 回到对话修订 | Context、MessageContent、ArtifactList、ReviewSummary、PreviewPanel |
| T3 多任务 Agent 控制台 | 项目/运行/待处理；L3 | 多个运行并存 → 找等待任务 → 审批/回答 → 查看失败证据 → 进入会话继续 | AgentBoardWorkspace、AttentionQueue、AgentRunInspector、Trace、会话区域 |

T1完整通过后再扩T2/T3。T2不添加代码执行要求；T3只展示来源给出的任务与关系，不实现新的多Agent调度器。所有模板共享runtime状态字典，但数据、连接、审批和结果确认保持分轴。

## 6. Fixture与场景控制

建立一套稳定ID的fixture项目，包含至少三个会话：正常运行、等待批准、失败待处理。基础数据同时提供两种语言的系统文案，用户输入与源文件正文保留原文。

使用显式动作推进的可重放reducer驱动示例；可选演示时钟仅在examples层，暂停/重置有明确入口。不能让公共组件自带setInterval自动“完成任务”。

场景集合：

1. 正常任务：草稿 → pending → 确认创建/发送 → 消息与工具逐步出现 → 产物 → 来源报告完成。
2. 需要审批：等待范围说明 → 用户批准 → 提交中 → fixture回执确认 → 工具开始；拒绝另有记录。
3. 结果未知：发送或审批已提交但确认丢失 → 保留内容 → 查询结果 → 确认或保持未知，禁止自动重试写入。
4. 中断恢复：消息部分完成 → 连接断开 → 切会话返回 → 重连 → 按ID/游标补齐，避免重复。
5. 长历史：补载旧页、连续流式文本、在历史中阅读，验证锚点与返回最新。
6. 审阅更新：旧revision上写反馈 → 新Diff到达 → 提示重新定位 → 修改反馈草稿 → 手动发送。
7. 上下文失败：附件上传失败/源文件失效/权限不可用；发送时提示实际可用引用，不静默假装已附加。

选择、搜索、面板尺寸和展开可立即更新；有业务含义的本地fixture动作也模拟pending与确认，便于以后更换适配器。结果区标注演示来源，不能把“测试通过”fixture当成本项目实际测试证据。

默认刷新重置fixture业务数据。只在示例适配器保存语言/主题/面板偏好；提供清除入口，不把完整会话、附件或敏感输出默认存入localStorage。URL用于恢复选择的场景，不能承诺刷新后恢复真实执行。

## 7. 展示内容与可访问性

- 所有区域提供Loading/Empty/Partial/Error/Success；刷新失败保留已有内容。空列表、过滤无结果、对象未选择和无权限使用不同说明。
- 展示真实长度的项目名、路径、任务标题、代码与日志；长文本可换行，代码区局部横向滚动，页面不横向溢出。
- 图标按钮有中文/英文aria-label；隐藏侧栏文字仍可辨识；Item主目标与尾部动作分离。
- Sheet/Dialog保持焦点约束、Escape关闭和焦点恢复；改变布局不重挂Composer或丢失选中文本。
- 屏幕阅读器播报阶段变化；生成中的每个token不触发重复播报。关闭面板不关闭任务。
- 触摸下操作不依赖hover。Diff行评论也有键盘入口；代码编辑/终端宿主插槽缺失时明确不可用。

## 8. 站点接入与文档

实施时在 `lib/example-manifest.ts` 添加“Agent 编码工作台”与三类模板入口，避免覆盖现有Agent Board条目；示例索引、首页场景、组件关联与文章采用同一来源。

新增公共组件同步Catalog/Registry/Docs Demo；准备 `AGENT-WORKBENCH.md` 说明安装、模型、受控回调、i18n、主题和服务适配。博客用完整场景讲解组件组合，引用实际截图及验证记录，不能先写“已接入真实服务”。

完成后捕获桌面/移动 × 浅色/深色截图，使用实际路由、固定fixture与字体加载状态。区域图用于说明职责，完整网页截图用于证明真实组合。源产品截图仅作研究参考，不成为项目默认资产。

## 9. 分批交付与验收

| 批次 | 对应组件阶段 | 交付 | 通过标准 |
| --- | --- | --- | --- |
| S0 | M0 | 页面地图、区域能力清单、fixture与基线 | 现有/候选/新增清楚，源码与契约差异有处置 |
| S1 | M1 | R1–R4网页 | 每个核心区域可以独立操作，深链可复现状态 |
| S2 | M2 | R5–R10网页 | 工具审批、文件审阅、产物/日志等没有假能力 |
| S3 | M3 | L1–L3组合页 | 一套状态贯穿多区，跨布局/宽度不丢草稿与对象 |
| S4 | M4 | T1完整页面 | 新任务→执行→等待→恢复→审阅闭环及导航通过 |
| S5 | M4 | T2/T3完整页面 | 使用同一公共区域组件，各自场景闭环通过 |
| S6 | M5 | 安装、目录、截图、文档与验证记录 | 全部必要检查通过；示例证据和真实服务证据分列 |

浏览器测试按用户动作断言可见结果，不只查组件是否出现。重点记录跨区域联动：侧栏切会话后正文/上下文/草稿同属一个ID；批准后只有对应工具更新；Diff反馈只进入对应会话；迟到响应不污染当前页面。

验收产物包含检查命令/结果、场景与视口、截图、未接服务列表、已知问题。真实模型、文件写入、Git操作、PTY与浏览器控制仍需组件计划M6单独验收。当前网页已进入实现和隔离验收，完成状态以 [实施记录](./agent-workbench-implementation-log.md) 为准。
