# Pi Agent Workspace 接入执行计划

日期：2026-10-10。状态：首轮 P0–P5 已实现，实际验证与边界见[实施记录](pi-agent-workspace-integration-log.md)。本计划承接 [工作台组件计划](./agent-workbench-components-plan.md) 的 M6 真实服务阶段；范围是本地单用户 Pi 接入示例。

目标是在 EasyuseUI 示例网页中选择项目、浏览历史会话、恢复上下文继续聊天，并展示真实模型输出、工具调用和运行状态。关闭网页或刷新后，可以重新读取已持久化的聊天记录。UI、服务接入、真实模型验证分别记录证据。

## 2. 第一版范围和完成条件

### 必须交付

1. 新增 `/examples/agent-workbench/pi/`，在现有示例总览提供入口；沿用紧凑工作台布局。
2. 连接本地服务，选择服务端配置的项目，列出该项目的托管会话和可读取的既有 Pi 会话。
3. 创建持久化会话，发送消息，显示真实流式回答、工具调用及结果，能够请求停止。
4. 打开历史会话并向上分页；展示用户/助手正文、工具记录、可显示的自定义消息和压缩提示，保留原始顺序与稳定身份。
5. 恢复托管会话继续聊天；既有外部会话以只读方式浏览，通过显式“复制并继续”创建托管副本后执行。
6. 浏览器刷新后恢复项目和会话选择，读取持久化历史；网页断开不自动终止后台运行，重新连接后对齐快照。
7. 服务重启后恢复历史与操作回执；不能把重启前未确认的执行自动补发或标记为完成。
8. 提供启动说明、项目与模型配置示例、故障恢复说明和分层验收记录。

### 后续范围

多用户账户、公网部署、调度与多 Agent 编排、PTY、Git/Diff 服务、附件上传、任意扩展 UI、完整分支编辑器、会话删除、自动恢复崩溃任务，以及完整工具审批系统均另行实施。queue/steer 第一版关闭；只有补齐服务、回执和测试后才打开相应能力。

第一版默认只启用经过核对的只读工具，不启用 Bash、写文件和未经检查的扩展。若后续增加写入能力，必须由服务端配置真实执行政策并补齐相应验证；网页不能仅凭展示一个“批准”按钮就声称工具受审批控制。项目目录配置用于选择工作环境，不等于操作系统沙箱。

## 3. 架构与责任

```text
Pi 示例页面
  └─ PiWorkspaceProvider + HTTP/SSE client
       ├─ 受控工作台快照、逐会话草稿、阅读锚点
       └─ 本地 Pi Host
            ├─ 项目配置、认证、能力与会话所有权
            ├─ 命令回执、事件游标、历史投影
            └─ 锁定版本 Pi SDK
                 ├─ 模型与工具执行
                 └─ Pi 原生会话文件
```

- **接入方式：** 优先 Node.js SDK，锁定 `@earendil-works/pi-coding-agent@1.1.0` 并在 P0 验证。全局安装仅用于核对，不作为项目运行依赖。SDK 若存在经验证无法解决的宿主兼容问题，再评估同版本 RPC 子进程；不同时维护两套后端。
- **传输：** HTTP 读写 API + 基于 `fetch` 的 SSE 读取器。消息发送与停止走命令 API，长连接仅传事件。服务定义可重连游标、心跳和背压处理，不依赖浏览器连接决定任务生死。
- **部署：** 保持 Next 静态导出。开发复用已有 3010 服务；Pi Host 默认候选端口 3012，启动前核对占用且允许配置。正式浏览器验收默认 3011 或已确认的隔离端口。
- **访问：** 默认监听回环地址，校验允许的 Host/Origin，API 和事件流使用服务凭据；凭据不进入 URL、静态构建或提交内容。远程浏览本机示例需 SSH 隧道或另行配置代理，不默认开放到公网。
- **存储：** Pi 文件是会话内容权威；Host 独立维护会话映射、命令账本和可重建索引。浏览器只保存 UI 偏好及可选草稿，不成为执行事实来源。运行数据放用户数据目录或明确忽略的本地目录。
- **分发：** SDK、认证、文件系统和请求逻辑仅进入 Host 与示例适配层，不进入 `components/blocks/` 的可分发依赖闭包。

## 4. 历史记录与会话所有权

### 4.1 读取和继续

- 服务端配置 `projectId → cwd` 与允许读取的会话目录。浏览器只提交不透明 ID，不接受任意文件路径作为读取或执行目标。
- 托管新会话使用 Pi 原生持久化管理器，不采用 `SessionManager.inMemory()`。
- 外部历史读取必须无副作用。先核对版本读取方法是否会自动迁移文件；必要时采用受限只读解析器或临时副本，不能因为打开网页而改写用户原始历史。
- “复制并继续”保留原始会话及分支上下文，并生成新的托管身份与来源关联；具体复制/分叉方法在 P0 用锁定 SDK 验证。UI 明示后续消息保存在副本。
- 托管会话由 Host 单一写入者持有；同一会话的命令串行，多标签页复用同一运行实例。第二个 Host 不能取得同一托管数据目录的写锁。
- 切换会话只改变订阅和视图，不自动取消旧会话任务。限制活跃运行数量并返回明确 busy 原因；第一版可设总并发为 1。

### 4.2 历史投影

- 区分“页面可读的原始分支历史”和“交给模型的有效上下文”。历史区沿选定叶节点的父链读取原始条目，保留压缩前可读消息；继续执行由 Pi 原生上下文恢复逻辑负责。
- 第一版显示默认分支及明确的分支提示；不把不同分支拼成一段对话。默认叶节点选择规则在 P0 验证，不能凭文件顺序自行推断全部语义。
- 不向页面透传全部原始 JSONL：系统上下文、隐藏自定义记录、凭据及内部扩展状态不作为普通聊天正文。未知条目使用有界的类型提示或明确忽略策略，并记录兼容诊断。
- 消息使用稳定 entry/message ID，流式块使用稳定 part ID；工具按 toolCallId 关联调用和结果，不能仅依赖显示文本或数组下标。
- 分页游标绑定 `sessionId + branch/leaf + snapshotRevision`，与 SSE 事件游标分开。建议初始每页 50 条，并限制响应字节数和单条输出大小。
- 历史索引按文件身份和版本失效，首次构建可后台进行；不能每次翻页都重新解析整个大文件。流式追加与历史快照通过版本边界合并和去重。
- 截断、损坏行、版本不兼容、不可访问文件分别显示 partial/error，保留已读取部分；大文件和未完成尾行不能导致页面永久 loading。

## 5. 命令、快照与事件协议

以下为 Host 自定义协议草案，不代表 Pi 已有同名 HTTP API。P0 固定类型和错误语义后实施。

| 接口 | 用途与结果 |
| --- | --- |
| `GET /api/pi/health` | 服务版本、协议版本和连接状态；不返回凭据 |
| `GET /api/pi/projects` | 可访问项目及执行能力 |
| `GET /api/pi/projects/:projectId/sessions` | 分页会话摘要，区分托管/外部只读来源 |
| `POST /api/pi/projects/:projectId/sessions` | 创建托管会话，携带 requestId |
| `POST /api/pi/sessions/:sessionId/copy` | 将允许访问的外部历史复制为可继续的托管会话，携带 requestId |
| `GET /api/pi/sessions/:sessionId` | 当前快照、能力、revision 和事件同步位置 |
| `GET /api/pi/sessions/:sessionId/history` | 绑定快照的历史页、旧页游标及截断信息 |
| `POST /api/pi/sessions/:sessionId/messages` | 提交文本和 draftVersion，返回命令回执与 runId |
| `POST /api/pi/sessions/:sessionId/interrupt` | 针对 runId 提交停止请求，避免停止后来启动的运行 |
| `GET /api/pi/operations/:requestId` | 查询创建、发送、复制、停止的确认结果 |
| `GET /api/pi/sessions/:sessionId/events` | SSE 订阅与断点恢复；超出保留范围时要求重新获取快照 |

事件信封至少包含 `protocolVersion`、`hostEpoch`、`sessionId`、可选 `runId`、`sequence`、`revision`、`type` 和 `payload`。Host 在每次启动时更新 epoch，客户端不能把旧进程的序号直接沿用到新进程。

### 5.1 防止重复执行

1. 所有写命令在调用 SDK 前持久化 requestId、目标、请求摘要及 pending 状态；同键同内容返回原回执，同键不同内容返回冲突。
2. 命令“已接受”和运行“已完成”分别表达。发送草稿仅在来源确认用户消息已接受后清理，且只能清理提交时的草稿版本。
3. 网络超时或确认丢失标记 unknown；先查回执和权威会话，不自动换 requestId 重发。
4. Host 崩溃可能发生在 SDK 执行与账本更新之间。P0 验证 requestId 与 Pi 条目的关联方式；无法证明结果时保留 unknown 并阻止重复写入，不宣称跨进程 exactly-once。
5. 停止请求返回成功只说明提交；取消状态需等待运行停止事实。已经产生的工具副作用不会因停止而回滚。

### 5.2 同步与映射

- 首次快照和后续订阅建立无缺口边界：获取快照时返回已纳入的事件位置，从该位置之后重放；缓冲缺失则重新同步快照。
- 重复事件丢弃，序号缺口请求恢复，跨 epoch 重建订阅。慢客户端只可合并文本增量为权威块更新，不能悄悄丢弃工具结束和回执事件。
- Pi 的消息更新映射为同一消息修订，工具开始/更新/结束映射为 `WorkbenchTool`。服务重启后的持久化消息与旧流式消息必须合并，不能出现重复正文。
- 运行状态沿用 `lib/runtime-status.ts`。完成判定需要锁定版本明确的 settled 语义并结合错误/取消事实；不能把单次底层 `agent_end` 无条件映射为 completed。
- 断线保持最后已确认状态并标记过期；重启后没有存活任务证明的旧 running 不能直接变绿色。未知来源状态保留原值。

## 6. 页面适配和文件安排

页面默认对话优先：左侧项目及会话，中间历史和输入框，详情按需展开，底部执行输出默认收起。缺少真实文件、审阅或终端能力时隐藏入口或说明原因，不能沿用 fixture 的成功内容。

复用 `AgentConversation.onLoadHistory` 和 `AgentComposer` 回调；新建服务 Provider，不让真实回执经过 fixture 的模拟 reducer。若现有示例框架与 fixture 强耦合，只复用公共区域组件和必要的展示适配，不进行无关的大规模重构。

| 拟定位置 | 责任 |
| --- | --- |
| `services/pi-host/` | 独立 Node 包、锁定 SDK、配置、会话读取/运行、API/SSE、账本及服务测试 |
| `lib/pi-workspace-protocol.ts` | 无 Node/SDK 依赖的协议类型，Host 与前端共享的契约入口 |
| `components/examples/pi-workspace/` | client、Provider、事件归并、快照转换、页面组合及示例文字 |
| `app/examples/agent-workbench/pi/page.tsx` | 静态路由薄装配，客户端连接服务 |

| `plans/pi-agent-workspace-integration-log.md` | 逐阶段实际结果、版本与证据 |

全部内置文字支持 zh-CN/en；公共组件新增文字进入便携 typed messages，示例文案使用独立资源。切换语言或面板不得重挂输入框、清空草稿或发送请求。草稿按 sessionId 隔离；历史补载保持阅读锚点，距底部不超过 64px 才跟随新内容。

## 7. 实施顺序和阶段门槛

| 阶段 | 工作内容 | 退出条件 |
| --- | --- | --- |
| P0 版本与契约 | 核对并行改动、SDK 导入和 GLIBC 兼容；锁定依赖；验证只读历史、复制继续、事件结束及 requestId 关联；固定协议与能力表 | 类型可用；临时目录中的会话读取/恢复实验通过；明确默认模型配置及可用性，未配置模型也能浏览历史 |
| P1 历史服务 | 项目白名单、连接认证、会话列表、只读读取、分页投影、分支/压缩处理、托管复制 | 浏览外部会话前后原文件内容及修改时间不因读取改变；两个项目不串数据；托管历史重启后可读 |
| P2 真实执行 | 新建会话、SDK prompt/subscribe/abort、工具映射、持久化回执、写锁、并发限制和 SSE 同步 | 服务集成覆盖发送、输出、工具、停止、重复请求、连接断开及不确定结果；具备凭据时完成真实模型最小调用 |
| P3 页面接入 | 新路由、项目/会话选择、数据五态、历史补载、流式渲染、输入和停止、深链恢复 | 实际网页完成选项目→新建→发送→历史→继续；无服务、空历史、请求失败均有可操作提示 |
| P4 恢复和边界 | 重连、进程重启、多标签页、并发命令、坏文件/大历史、语言与无障碍 | 通过下节场景；没有重复发送、串会话、假取消或假完成 |
| P5 交付 | 文档、示例入口、隔离验证、真实模型浏览器验收、实施记录和按规则 Git 交付 | 必需检查通过；分别记录模拟/本地/真实模型证据；远端分支 SHA 验证完成 |

阶段按 P0 → P1 → P2 → P3 → P4 → P5 推进。首个可审阅成果是只读历史浏览，最终验收要求真实发送与恢复上下文均完成。真实模型配置缺失时可继续历史和契约工作，但真实服务验收保持未完成。

## 8. 验收矩阵

| 范围 | 必测场景 | 通过标准 |
| --- | --- | --- |
| 持久化 | 新会话两轮对话、刷新网页、重启 Host、重新打开 | 已确认消息保留，身份和顺序一致；运行中的崩溃场景单独表达不确定性 |
| 旧会话 | 外部会话只读打开、复制并继续、分支和压缩记录 | 原文件不被迁移/覆写；副本独立；页面历史与实际模型上下文各按来源规则恢复 |
| 上下文 | 第一轮保存独特事实，关闭并恢复后进行依赖该事实的追问 | 检查恢复的 Pi 上下文及真实模型输出；只有页面重绘不算通过 |
| 流式与工具 | 多段文本、工具成功/失败、有界长输出、未知内容类型 | 块不重复，调用与结果正确关联；脱敏后展示/复制；缺失退出码不补成功值 |
| 命令确认 | 双击发送、两标签同键请求、回执丢失、执行后账本未更新即崩溃 | 同键不重复调度；无法确认时锁定 unknown，不自动重试 |
| 停止 | 正常停止、确认迟到、旧 runId 停止请求 | 等待来源确认；新运行不被误停；已产生内容保留 |
| 事件同步 | 重复、乱序、缺口、快照期间追加、过期游标、Host epoch 改变 | 对齐权威快照，无漏掉的完成/工具记录，不把重连当作重新执行 |
| 隔离 | A 请求迟到时已切 B、同项目多会话、跨项目 ID、第二个 Host | 不串历史或清错草稿；越权 ID 拒绝；托管目录单写者成立 |
| 读取恢复 | 无服务、无凭据、空目录、拒绝访问、损坏/未完成 JSONL、刷新失败 | 正确区分空/错误/部分；同对象已有内容保留；浏览历史不强制模型在线 |
| 长历史 | 至少 1,000 条消息、分页同时流式、单条大工具结果 | 记录响应大小、首屏时间和滚动锚点；无重复/丢失；不预先宣称性能 SLA |
