# 页面首开与切换速度：临时执行计划

日期：2026-10-09。状态：T0–T5 执行完成。实施、测量、回归及交付证据见 [执行记录](./temporary-page-loading-execution-log.md)。工作台 JS 目标达到；部分就绪时间目标未达到，保留原门槛与实际结果。

用户确认的问题是“页面首次打开或切换时慢”。本计划聚焦该问题，承接已有 [优化实施记录](./optimization-and-blog-implementation-log.md)，保留已经完成的 Demo 按需加载、源码按需读取和重型引擎加载限制。

## 1. 目标与执行边界

先建立同源码的开发/生产对照，再按证据减少首屏依赖与导航等待。优先交付可访问的独立生产预览和前后测量报告，之后逐项优化；不把开发环境的脚本大小当成生产包大小。

- 保留共享3010开发服务，不在共享目录运行可能覆盖 `.next` / `out` 的构建；采用隔离源码快照及独立输出。
- 检查3011及候选端口的进程归属；被占用时使用空闲端口，不终止其他进程。
- 当前工作区有并行修改，特别是i18n、Demo loader、清单和SiteFrame。按文件/代码块合并，禁止覆盖、reset、clean、stash或宽泛暂存。
- 不改变会话、草稿、上下文、运行、审批、URL与历史返回语义；性能优化不能通过移除功能或展示假就绪达标。
- 本轮不升级Next/React、不更换构建工具、不改宿主GLIBC。当前主机GLIBC 2.28，沿用Webpack；开发服务重启不作为首个优化措施。
- 先处理示例和站点层。若实测确需修改可分发组件或i18n基础层，补充兼容与独立安装验证。

## 2. 初步观测：只作为排查线索

来源：本次对当前3010开发服务的本机Chromium采样；1440×900、新浏览器上下文、未限速。服务已运行，不能称为全冷编译测试。以下每路由浏览器首开仅一轮，尚非稳定性能基线。

| 路由                             |   TTFB | FCP（首次内容绘制） | load事件 | JS解码后体积 |
| -------------------------------- | -----: | ------------------: | -------: | -----------: |
| `/`                              |  205ms |               628ms |   1570ms |     19.13MiB |
| `/components/`                   |  552ms |               984ms |   1854ms |     22.11MiB |
| `/docs/button/`                  |  606ms |               960ms |   2091ms |     22.04MiB |
| `/examples/agent-workbench/app/` | 1730ms |              3968ms |   4983ms |     22.82MiB |

额外观测：点击首页→组件目录约1593ms，目录→Button文档约2763ms，口径为点击至目标标题可见并经过两次动画帧；包含自动化开销。热HTTP各采三次，TTFB约373–752ms。load、FCP、标题出现均不等于完整交互就绪。

源码与构建产物线索：

- 当前为 `next dev --webpack`。首屏公共开发运行时约11.9MiB，工作台页面开发chunk约5.8MiB；均含开发包装等开销。
- [workbench-demo.tsx](../components/examples/agent-workbench/workbench-demo.tsx) 当前2115行，集中导入多种页面与区域。文件长度不是性能结论，需以生产依赖图和实际下载确认拆分收益。
- [SiteI18nProvider](../components/site/site-i18n-provider.tsx) 及公共i18n链路带入整站/组件资源、CRM文案与页面元数据；实际贡献需生产测量。
- 主要导航大量使用 `prefetch={false}`。这是此前阻止重型Demo被间接加载的措施，不能全局撤销。
- 目录已采用轻量预览，Demo使用显式动态导入；源码浏览器主动加载资源。不要重新执行已完成的“所有Demo懒加载”改造。

核心路由为首页、组件目录、Button文档、Agent工作台app；回归加入词典、博客、工作台regions/layouts与一个Canvas主动预览。导航路径至少覆盖首页→目录→Button、示例目录→工作台，以及工作台内部home→session→review→settings→返回。

“真实控件可用”使用语言切换、受控输入和面板切换等无服务副作用动作，并断言DOM结果。不要把元素出现、骨架出现或networkidle当成交互就绪。

报告保存原始样本、中位数和范围；样本少时不宣称可靠p95。JS原始字节、解码后字节、gzip估算和真实传输编码分别列示。共享负载异常保留原记录，必要时增加同条件复测，不挑最快样本。

T1决策：若生产预览已显著改善，先交付预览供日常查看；后续优化以生产剩余瓶颈为准，不为降低开发chunk数字引入大范围重构。

## 8. 验收指标与回退

以下为执行前的候选目标，T1建立生产基线后固定适用路由与门槛；不能用降低门槛掩盖失败。

| 指标            | 目标/判定                                                                         |
| --------------- | --------------------------------------------------------------------------------- |
| 正确性          | 所有必要行为回归通过；无新增hydration/pageerror、草稿丢失、权限或状态语义变化     |
| 初始依赖        | 非当前页面/面板专属重型模块从目标首屏移除；非CRM路由无CRM专属资源                 |
| 工作台首屏JS    | 对生产基线争取减少≥20%；若已很小或拆分无收益，记录未达标/不采用，不增加无效复杂度 |
| 工作台就绪/导航 | 对原先慢路径争取中位数改善≥20%；同时报告绝对毫秒、范围和其他路由变化              |
| 回归调查线      | 关键路由中位数变慢超过10%且超过100ms时，增加同条件复测并排查；确认回归则回退候选  |
| 安装与展示      | 既有组件安装、语言、主题、源码查看和主动预览继续有效                              |

回退只撤销本任务候选对应的文件/代码块或独立提交，保留并行修改；不通过reset/clean恢复整个工作区。懒加载回退保留状态所有者，字典回退同时恢复生成逻辑，预取回退恢复原导航策略。隔离预览只停止本任务启动的进程。
