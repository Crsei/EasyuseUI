# EasyuseUI 首页与文档站改版计划

日期：2026-10-09
状态：D0–D5 已实现并通过本地验收（2026-10-09）。详见 [实施记录](./homepage-and-docs-redesign-log.md)；公开部署及远程CI未在本轮执行。

将首页改为突出真实工作台场景的产品入口，将文档改为便于检索、阅读、预览和安装的组件手册。首页用 Agent、Work Items、Canvas 的组合效果说明 EasyuseUI 的价值；文档帮助使用者从一个组件走到可运行的界面。

承接 [优化与 Blog 计划](./optimization-and-blog-plan.md)，复用已建立的 Manifest、按需 Demo、组件目录、Blog 和 Registry 管线。遵循 [设计规则](../Design-rules.md)、[组件契约](../Component-Specification.md)、[交互模式](../UI-PATTERNS.md) 和 [国际化约定](../I18N.md)。本计划针对站点呈现与内容组织，工作区内的紧凑交互契约继续有效。

## 3. 站点信息架构

主导航收敛为 **文档、组件、示例、Blog**；右侧放搜索、主题、语言和明确的代码仓库入口。视觉词典、样式工作台、滚动实验归入“资源”，可放菜单及页脚；工作台从示例库和首页场景进入。原“组合模块”入口不再固定指向一个TaskPanel组件，改为组件目录对应分类。

| 路由 | 定位与计划变化 |
| --- | --- |
| `/` | 品牌定位、场景主视觉、精选组件、源码接入、近期优化 |
| `/docs/` | 阅读起点：安装第一个组件、理解受控模式、组合工作台 |
| `/docs/installation/` | 保留安装入口，按步骤呈现环境前提、命令、主题与验证 |
| `/docs/[slug]/` | 保留现有组件slug和锚点；统一模板，增加结构化内容 |
| `/components/` | 视觉组件目录：搜索、分类、缩略图、主动预览和文档链接 |
| `/examples/` | 场景画廊：Agent、Work Items、Canvas；CRM按完成/验证状态纳入 |
| `/blog/` | 优化方案、过程和效果证据；首页只引用已有文章摘要 |
| `/dictionary/`、`/style-workbench/`、`/scroll/` | 作为资源入口保留地址和独立职责 |

当前 Work Items 完整示例入口为 `/examples/work-items/`，`/workspace/work-items/` 已是兼容跳转；新内容链接主入口，保留旧地址和查询参数行为。Agent与Canvas沿用当前工作区路由，不为导航整齐而搬迁。全局导航支持子路由激活态，但 `/docs` 总入口与具体文档高亮分别管理。

## 4. 首页视觉与内容方案

### 4.1 视觉方向

采用中性底色、清晰字体、充足留白和真实产品界面作为主视觉。保留现有紫色作为少量品牌强调，用于主要行动、选中态和重点文字；移除首屏点阵外壳对TaskPanel的过度强调，让完整工作台成为视觉中心。

- 页面主体最大宽度建议1280px，Hero文案宽度约880px；桌面标题56–64px、窄屏36–40px，最多两至三行；正文16–18px。以上为首页展示规格，不改变工具页20px标题与32px控件契约。
- 全局Header建议64px，导航与工具单行；中等宽度提前切换菜单，不能靠压缩字号容纳所有入口。首页区块上下间距64–96px，窄屏40–56px；主视觉圆角12–16px、细边框、有限阴影。
- Light/Dark都需专门检查截图和分隔层级，不依靠模糊渐变、自动滚动、发光或装饰动画制造层次。新增站点布局尺寸作用于站点容器，颜色继续使用共享语义token；不改全局theme去适配单张首页图。
- 普通站点标题和预览外框可采用展示规格，嵌入的组件保留其正式密度与交互尺寸；缩略图不是缩小后的可操作控件。

### 4.2 首页区块顺序

| 顺序 | 区块与建议内容 | 行动与验收 |
| --- | --- | --- |
| H1 | 居中Hero；建议标题“从组件，到完整的工作界面。”；副文案说明React源码组件、任务管理和Agent工作台 | 主行动“开始构建”到安装；次行动“查看示例”到示例库。首屏不同时放多个实验入口 |
| H2 | 宽幅场景预览：Agent工作台 / Work Items / 流程画布，默认Agent；显示场景名称、短说明和本地演示标记 | 三个Tab切换真实截图；“打开完整示例”到对应页面。1440×900与390×844首屏能看到主视觉开头 |
| H3 | 精选组件展示区：基础交互、任务与数据、Agent执行、工作区布局，6–8个有差异的片段 | 每块包含轻量预览、名称、用途和文档入口；避免重复展示多个相似Button变体 |
| H4 | 组合路径：选择组件 → 安装源码 → 组合页面，以一个真实工作台列出所用组件 | 能从场景回到具体组件，并复制与当前Registry一致的安装命令 |
| H5 | 最新优化与案例：2–3篇Blog文章，显示题目、摘要、实现/验证状态 | 阅读文章或打开对应示例；不展示未经测量的提升数字 |
| H6 | 简洁收尾与页脚：安装、组件、示例、资源、仓库 | 入口完整，没有重复的大段口号或空功能链接 |

工作台截图从本项目固定fixtures生成，提供深浅主题和适当窄屏版本，记录场景/版本/尺寸。首张关键图片优先加载，其他图延迟加载并声明宽高。首页默认不挂载Canvas、完整Agent看板或全量组件Demo；少量轻控件可交互，重场景通过明确入口进入。演示UI和真实服务能力的边界在场景说明中可见。

## 5. 文档框架与组件详情

### 5.1 布局与导航

桌面采用“左侧文档目录 + 中间正文 + 右侧页内目录”。建议总宽1440px，侧栏240px，正文阅读宽680–760px，右目录192px；API表格与宽预览在正文列内按模板扩展，不能挤出整页横向滚动。

- ≥1280px三栏；768–1279px保留侧栏，页内目录改顶部菜单；<768px文档目录使用Sheet，正文上方保留面包屑和“本页目录”。阈值在中英文下验收，必要时提前折叠。
- 文档主内容使用页面滚动；侧栏限制在Header以下高度并独立滚动，页内目录吸顶。路由切换保留侧栏位置并让当前项可见，不能每次重置到顶部；正文前进/后退尊重历史位置。
- 侧栏按“入门、基础交互、数据与任务、Agent与会话、Canvas、工作区布局”组织；资源页另组。折叠状态与当前页独立，当前组自动展开；未知条目须有兜底分组，不因分类变化丢链接。
- `docGroup/docOrder`是文档展示元信息，与Registry installType、现有displayCategory分开；从Manifest生成侧栏，禁止维护第二份组件清单。
- 页内目录来自实际section定义，显示安装、使用、变体、API、状态/可访问性、源码等有效章节。锚点ID不随语言变化，保留已有 `installation/usage/api/example/source`；粘性Header不遮挡标题。

### 5.2 统一详情模板

推荐阅读顺序：面包屑 → 名称/用途/关联入口 → 主预览 → 安装 → 最小用法 → 常见变体 → API → 状态与交互说明 → 源码文件 → 相关组件/上下篇。

| 模块 | 行为与内容 |
| --- | --- |
| DocHeader | 名称、简短用途、所属组、可选完整示例入口；文档状态只来自已验证元数据 |
| ComponentPreview | 预览/示例代码切换，复制、重置、打开完整示例；仅为适用组件展示尺寸/主题/状态选择器 |
| InstallationBlock | 默认pnpm，可提供经验证的npm/yarn/bun对应命令；说明现有项目前提和依赖，复制内容与显示一致 |
| Usage/Variants | 最小可运行片段优先；按组件选择2–4个有意义的变体，不给所有组件填相同空章节 |
| APIReference | 属性/类型/默认值/说明分列，复杂类型链接对应定义；标注受控数据与调用方职责，移动端局部横滚 |
| StateExamples | 对有数据/异步行为的组件展示加载、空、部分、错误与恢复；对基础控件展示相关交互态，不机械套运行状态 |
| SourceBrowser | 按源码、CSS、模型等文件选择；默认折叠长内容，保留完整读取/复制入口；清楚区分仓库源码和安装后的便携源码 |
| RelatedContent | 关联组件、真实组合示例和优化文章；上下篇按文档分组顺序生成 |

预览默认只加载当前组件的一份演示；重型组件使用明确加载入口，必要时打开独立示例，不在文档内塞完整工作台。预览/代码切换保留当前演示草稿，显式重置才清空。主题试验使用ThemeBoundary并覆盖Portal，不能污染站点主题；语言切换不重挂载示例。

现有示例文件可包含演示Provider和fixture，不能将任意源码片段标作“复制即可生产接入”。安装命令读取统一registryUrl/发布配置；公开构建不得产生localhost安装地址。静态导出不依赖请求时的 `window.location` 来补救错误的构建配置。

### 5.3 文档内容建设

`/docs/` 改为简短介绍、三条学习路径和分类入口，不再列出全部组件卡片。优先补“安装与主题”“受控组件与调用方责任”“国际化”“Registry与源码接入”“组合工作台”指南。

首版保留TSX指南和Manifest组件元数据，增加结构化sections/variants/related links的可选字段与文档内容索引。指南文案和代码例子各有明确来源，生成TOC/搜索时引用相同结构。新增指南slug先检查与组件slug冲突，加入静态路由生成及sitemap。

先改造Button、DataTable、ToolCall、WorkItemsWorkspace、WorkflowCanvas五种代表页面，覆盖简单控件、数据区域、敏感操作、组合布局及重型预览；模板稳定后迁移其余页面。保留既有安装ID、源码依赖与文档地址。

## 6. 搜索、组件目录与示例库

- 新增站点级DocSearch，复用现有CommandPalette与Dialog/键盘契约。Header按钮和Cmd/Ctrl+K打开；中文名称、英文名称、slug、别名及用途可检索，结果按组件、指南、示例、文章分组，支持章节链接。
- 搜索索引由构建生成，包含可公开的标题、摘要、稳定路径和章节信息；打开搜索时再加载索引，不导入组件实现、Demo或整份源码。首版无需远程搜索服务、账户或遥测依赖。
- 支持方向键、Enter、Escape及关闭后焦点归还；输入法组合期间不误提交。索引加载失败有重试和目录入口；无结果提供关键词建议，不能假装加载完成但无内容。
- `/components/` 保留现有query/category/preview URL行为；增加“网格/列表”展示选择，默认视觉网格由轻量缩略图构成。每张预览具有文档主入口，交互预览需主动打开，不能因滚动浏览而自动挂载全部Demo。
- `/examples/` 从手写单行链接升级为场景画廊。ExampleManifest记录稳定ID、标题/翻译、描述、canonical href、深浅缩略图、关联组件ID、文章ID和验证状态；Agent、Work Items、Canvas为首批，CRM待其页面与证据达到可展示状态后加入。
- 首页精选、示例库、组件详情“用于这些场景”均引用同一ExampleManifest；禁用不可用的占位链接。检索排序和推荐由明确配置决定，不编造访问热度、下载量、星标或客户Logo。

新增站点组件属于 `components/site/` 或 `components/docs/`，不默认注册为可分发组件；只有明确可复用的公共能力才进入ui/blocks及Registry。

代码高亮保留构建端执行，不把Shiki引入客户端。长源码仅用CSS隐藏不会减少HTML/RSC负载；需先测量，必要时构建生成按slug/文件ID读取的静态代码资源，主动展开才加载。文件索引只来自受控Manifest，完整源码和复制文本同源，不接受任意文件路径读取。

保持 `output: export`、trailingSlash及Webpack构建方式。SEO补齐页面description、canonical、静态分享图和sitemap；当前语言为客户端切换，不冒充已提供独立英文索引页。是否增加语言路由另立迁移范围。修改框架代码前阅读安装版本Next文档。
