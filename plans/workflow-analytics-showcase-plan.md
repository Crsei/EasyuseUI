# 工作流分析与 Dashboard 示例展示计划

日期：2026-10-09
状态：S0–S6 已实现，十种场景、来源下钻、布局保存恢复、构建器与展示证据已完成；验收限于本地 fixture 和独立消费。配套 [组件计划](./workflow-analytics-components-plan.md) 与 [实施记录](./workflow-analytics-implementation-log.md)。

展示目标是走通“看见问题 → 理解口径 → 定位对象 → 回到工作视图”的链路。以一组确定性工作项、历史事件、关系、执行和容量数据，分别演示 Views、Charts、Dashboards，再验证三者共享筛选和对象身份。

## 1. 页面组织与入口

新增统一入口 `/examples/workflow-analytics/`，作为全窗口示例；示例库、组件文档和首页精选链接此入口，保留现有 `/examples/work-items/`、`/workspace/agents/`、Canvas的独立职责。

| 页面模式 | 路由参数建议 | 内容与范围 |
| --- | --- | --- |
| 项目概览 | `?view=overview` | P0默认；状态指标、完成趋势、状态分布、关注工作项 |
| 工作关联 | `?view=traceability` | P0；Idea→Task→Session→Run→Artifact关系列表、详情和来源 |
| 图表目录 | `?view=charts&chart=work-item-aging` | P0随组件阶段扩展；按问题分组的单图示例，可查看数据与API |
| Agent执行 | `?view=agents` | P1；实际执行区间、结果/验收、Token/Cost/Duration与原始Run |
| 资源计划 | `?view=resources` | P1；成员×日期负载、容量解释、未安排项与排期视图 |
| 迭代进度 | `?view=delivery` | P1可选；燃尽/燃起/速度与scope变化，不预设所有项目采用Sprint |
| 流程效率 | `?view=flow` | P2；CFD、周期时间、状态停留和历史时点明细 |
| 风险分析 | `?view=risk` | P0规则列表嵌在概览，P2独立页增加依赖与条件化预测 |
| 自定义布局 | `?view=custom` | P1；由已实现模板复制，在明确编辑模式中调整Widget |
| 分析构建器 | `?view=builder` | P2最后开放；口径/维度/分段/图型配置与查询预览 |

未交付模式不呈现可点击空入口；访问尚不支持参数时显示明确说明并回到已支持视图。`view`控制业务场景，Calendar月/周或Timeline刻度属于工作视图参数，不混作页面模式。

URL适配器管理项目、范围、timeField、粒度、时区、有效过滤、选中widget/bucket/entity；公开示例ID可序列化，真实消费方使用受控查询token。未知参数有白名单回退；刷新、分享、前进/后退保持一致解释，不覆盖有效深链接。

## 2. 首屏与统一布局

首屏顺序固定为：整体状态 → 进度变化 → 问题分布 → 具体关注对象。项目概览默认最多4个KPI、2张主图和1个任务列表，不把图表目录直接当Dashboard。

```text
WorkspaceShell
├─ Sidebar：概览 / 工作关联 / Agent / 资源 / 进度 / 流程 / 风险
├─ Header：示例项目 · 工作流分析                    数据时间 · 刷新
├─ GlobalFilters：时间字段/范围 · 成员 · 状态 · 项目
├─ Metrics：有效范围工作项 / 已完成 / 进行中 / 明确阻塞
├─ PrimaryCharts：完成趋势（宽） | 状态分布（窄）
├─ AttentionList：超龄 / 阻塞 / 逾期工作项
├─ Drilldown：点选集合 → 任务列表 → 详情/完整工作视图
└─ 默认折叠：模拟数据说明 / 场景切换 / 重置 / 组件文档
```

所有聚合由fixture数据计算，示例中的128/84/32/12等宣传排布数字不直接写成结果。阻塞是可叠加条件时，其数量不与完成/进行中构成互斥相加。标题明确“按截止日期”“本期完成”等时间语义。

桌面为12列网格，主趋势8列、分布4列；中屏调整为6列和适当换行，390px单列，图表保持标题与摘要，提供数据表和展开。详情用Inspector/Sheet；显示关注项，不在每个Widget外再嵌套多层Card。

## 3. 示例模板与完整操作流程

| 编号 | 模板与要回答的问题 | 必须走通的路径 |
| --- | --- | --- |
| EX01 | 项目状态：现在有什么需要处理？ | 点击“明确阻塞”KPI → 同快照阻塞项列表 → 任务详情 → 关闭返回原图 |
| EX02 | 完成趋势：本周是否持续交付？ | 点击某日柱/点 → 本日完成项 → 查看其当前状态；重新打开的任务保留历史完成事实 |
| EX03 | 工作项年龄：哪些任务长期停滞？ | 切年龄/状态停留 → 点选异常项 → 展示创建或入状态时间依据；缺历史时明确不可计算 |
| EX04 | 工作关联：一个Idea如何产生工作成果？ | 选择Idea → 任务/Session/Run/Artifact列表 → 双向定位；未关联、多个关联、未知/已移除对象可读 |
| EX05 | Agent执行：执行结束是否产生验收成果？ | 实际运行区间 → Run详情 → 产物/验收；Tokens或费用点 → 原始观测表，保持币种与包含关系 |
| EX06 | 资源计划：哪些日期容量紧张？ | 点热图格 → 人员/日期分配清单与容量 → 打开Timeline；授权时通过既有改期表单提交并刷新聚合 |
| EX07 | 范围变化：为什么进度线改变？ | Burnup scope上升点 → 新加入/估算变化项；Burndown期初理想线与实际线解释；Velocity查看承诺/交付 |
| EX08 | 流程效率：工作在哪里积压？ | CFD某日某状态 → 当时成员 → 当前详情；周期时间点 → 状态事件与口径说明 |
| EX09 | 风险解释：事实与预测各是什么？ | 规则风险 → 触发证据；预测区间 → 方法/样本/假设 → 历史样本和待完成项，不生成未来任务 |
| EX10 | Dashboard编辑：如何保留团队常用分析？ | 从固定模板复制 → 添加/重排/调整尺寸 → 保存；拒绝保留草稿，unknown先核对 |
| EX11 | 分析构建：一个问题怎样转为查询？ | 选择count/assignee/status/stacked-bar → 预览 → 点柱段 → 明细；不兼容单位或图型时可解释阻止 |

默认点击只下钻，显式“应用为筛选”才改变同页其他Widget。图例隐藏只改变显示，分母保持原口径并提示；提供重置、清除选中和清除筛选的不同动作。

“打开工作视图”优先在本示例的ViewAdapter中复用WorkItemList/Board/Table/Timeline/Calendar，以保证同一份数据。跳转现有独立示例只能标作“查看组件示例”，不能因其拥有另一份fixture而冒称展示当前分析集合；若需跨路由保持集合，使用共同的适配器和稳定数据集ID。

## 4. 图表目录与单组件文档

按用户问题组织目录：状态/进度、流程效率、资源、执行成本、风险。底层Bar/Line/Area/Donut/Scatter/Heatmap仍有独立组件文档，专业模板另写输入要求和指标口径，不能只有颜色变体。

每个示例提供五个可切换区域：

1. 图形预览：当前条件、单位、数据质量和选择态。
2. 聚合数据表：与图形同一result，点选可进入原始记录。
3. 口径说明：样本、分母、时间字段、时区、估算/历史限制。
4. 最小用法：受控query/result/onDrilldown示例，不把本地fixtures当SDK。
5. 状态场景：零、未采集、部分、错误、无权限和恢复；按真实组件需求显示。

Chart组件目录仅静态缩略图或轻量摘要，主动预览时才加载一个目标图。Dashboard预览只加载该模板实际使用的图型；不遍历所有DemoLoader隐藏挂载图表。颜色/布局实验限于ThemeBoundary，不改变工作项状态色。

## 5. 确定性数据与可解释计算

数据集建议覆盖两个项目、至少四名成员、三个Agent、多模型与两种币种、多个迭代及90天时间窗口。具体条数由C0固定；基准日期固定为2026-10-09，提供明确时区和业务日历。数据规模是测试fixture，不宣传为真实用户或真实执行数据。

| 数据集 | 包含内容 | 用途 |
| --- | --- | --- |
| 正常项目 | 当前工作项、明确业务状态、创建/实际开始/完成时间、关系、计划日期 | KPI、趋势、年龄、五布局下钻 |
| 历史重放 | 期初快照，状态、scope、估算、归属、重开、归档和删除事件 | CFD、周期时间、燃尽/燃起及历史成员 |
| 工作关联 | 明确Idea/Task/Session/Run/Artifact边；含多对多与孤立对象 | 关系视图，不凭标题自动关联或推算转化率 |
| 执行与用量 | Run实际区间、等待阶段、审批、产物验收、区间usage、重复与inclusive观测 | 运行与验收分离，成本/时长/父子去重 |
| 资源容量 | 成员工作日历、假期、每日容量、分配份额与未知估算 | 热图容量、分配单位、零容量和未知情况 |
| 风险与预测 | 确定阈值触发事实；足够/不足历史、范围突变及固定种子预测结果 | 解释和降级，不预设预测正确 |

除了大数据生成器，还须有可手算的小fixture：逐项列出期初状态、事件与预期聚合。计算测试的expected独立编写，不调用同一聚合函数生成答案。至少覆盖一次重开、一次移出范围、一次估算修正、一个无创建时间项与一个跨时区完成事件。

前端真实查询不参与本阶段；示例适配器实现同一AnalyticsQuery接口与可控异步返回。内存修改同时更新相应事件/聚合数据或显示刷新等待，不通过直接篡改图形数值来模拟业务成功。

## 6. 状态场景矩阵

| 场景 | 预期呈现/恢复 |
| --- | --- |
| 空项目 / 筛选无匹配 / 真实0 | 三者文案不同；0值点可见且不被格式化丢失 |
| 当前快照有数据、历史未采集 | 当前分布正常，趋势/周期Widget显示历史能力缺失；不回填零折线 |
| 有期初无完整事件 / 只有部分时间段 | 标覆盖边界/缺口，缺口断线，不能推导完整CFD |
| 刷新失败 | 同查询旧值保留并标过期；单Widget可重试，其他卡片继续可用 |
| 项目切换与迟到响应 | 旧queryKey的结果不覆盖新项目；不同widget回执不串用 |
| 权限撤回 / 明细权限小于聚合权限 | 旧受限明细清除；可见数量与限制有说明，不泄露标题或伪造全量 |
| 点击历史阻塞桶 | 显示当时集合及历史标记，不能仅套当前status过滤 |
| 多负责人、多标签、父子工作项 | 声明计数/分摊规则；汇总按实体去重，不能重复计入总量 |
| 事件重复、乱序、修正、重开 | 正确去重/重算；变化说明可查，不能把所有重开视为数据错误 |
| 缺失/NaN/负数/未知单位 | 无效值隔离并标覆盖；可为负的差值与不可负的任务数分别校验 |
| 无容量、容量0、估算未知 | 不显示虚假的利用率；“不可用”“未知”和“无分配”不同 |
| Token包含性未知/混合币种 | 分组说明，禁止重复相加或擅自汇率转换 |
| 预测不足/模型过期 | 显示不支持或过期依据；不制造平滑预测线 |
| 配置保存被拒绝/unknown | 草稿可恢复；unknown先核对，重挂载不能假装保存成功 |
| 高频刷新与图表选择 | 当前选择不随数组索引漂移；被删除对象显示说明，阅读位置不被抢走 |

## 7. 响应式 无障碍与导出展示

- 1440/1024/768/390px覆盖深浅主题、中英文；固定模板图表与关注列表在首屏/近首屏形成明确层级。英文长维度名有完整读取方式，0与未知值都能辨认。
- 每张图有标题和文本摘要；Tab到图表交互入口，方向键/受控游标或数据表访问数据，Enter下钻，Escape关闭并归还焦点。触屏不依赖hover Tooltip，交互控件命中至少44px。
- 对高点数图不创建一万个Tab停靠；精确记录可从分页表定位。图例可键盘操作，筛选变更播报概括，不逐点抢读屏。
- CSV基于当前结果与权限生成，带范围/时区/口径说明并安全处理公式前缀；P1图像导出包含图名、单位、时间和本地模拟标记。导出前后数量一致，不能把只加载第一页称完整导出。
- 截图显示样式；记录下钻/筛选/保存等实际操作步骤证明行为；预测表现通过回测或来源证据说明。三类证据分别记录。

## 9. 验证与 Blog 内容

组件改动按主计划运行lint/typecheck/build、Manifest/i18n/Blog检查、浏览器与安装测试；复用现有开发服务前检查进程归属，生产验证使用不会覆盖在用产物的隔离环境。文档规划阶段只检查文件、链接与契约一致性。

性能采集分开记录“事件聚合”“图表绘制”“筛选响应”“下钻查询/列表渲染”；聚合输入量、绘制点数、Widget数、主题、语言、浏览器与源码快照必须记录。基线后再制定门槛，不用一张流畅截图宣称支持大数据。

Blog按“问题 → 指标口径 → 组件组合 → 交互路径 → 异常恢复 → 验证结果”组织。首篇展示项目概览和精确下钻；后续分别展示资源/Agent成本、范围变化、流程效率与风险。图表数据公开标记为模拟；截图与数字对应同一fixture，不宣传项目不存在的客户数据或收益。

最终验收必须能回答：这个数是什么、统计了谁、截至何时、哪些数据缺失、点击后为什么得到这些对象、下一步允许做什么。真实团队指标与预测可信度由消费项目接入完整历史和服务权限后另行验收。
